Pool-API verbinden

Verbinde opencode, Cursor, Continue oder jeden OpenAI-kompatiblen Client mit dem SINator Key-Pool. Rate-Limits und tote Keys werden automatisch erkannt und getauscht.

Pool-Router — EINE Base-URL, 10 Proxys, Auto-Failover

Einzige öffentliche URL. Der Router verteilt automatisch auf 10 Proxys mit je eigenem API-Key. Bei 413/429/412/5xx wird zum nächsten Proxy gesprungen. Kein gegenseitiges Blockieren, kein manuelles Pool-Wechseln.

baseURL: https://sinatorpool-router.delqhi.com/inference/v1

apiKey:     7avN...

Lokal am Mac (ohne API-Key): http://localhost:9998/inference/v1
opencode — komplett einrichten

2. API-Key in ~/.zshrc (dann source ~/.zshrc):

export FIREWORKS_API_KEY="<DEIN_API_KEY>"

Bestehende opencode.json? Nur den provider.fireworks-ai Block in dein existierendes "provider"Objekt einfügen.

Cursor / Continue / Python SDK
Remote-Clients nutzen dieselbe Pool-Router-URL

Cursor: Settings → Models → Neuen Provider

Base URL: https://sinatorpool-router.delqhi.com/inference/v1
API Key:  <DEIN_API_KEY>

Continue (VS Code): In ~/.continue/config.json

{ "models": [{
  "provider": "openai",
  "apiBase":                   "https://sinatorpool-router.delqhi.com/inference/v1",
  "apiKey": "<DEIN_API_KEY>"
}] }

Python:

from openai import OpenAI
client = OpenAI(
  base_url="https://sinatorpool-router.delqhi.com/inference/v1",
  api_key="<DEIN_API_KEY>",
)

Nur EINE URL — für alle

https://sinatorpool-router.delqhi.com/inference/v1 — eine Base-URL für alle Clients (lokal, remote, Cursor, Continue, Python). Der Router verteilt auf 10 Proxys mit Auto-Failover. Lokal am Mac geht auch http://localhost:9998/inference/v1 ohne API-Key.
